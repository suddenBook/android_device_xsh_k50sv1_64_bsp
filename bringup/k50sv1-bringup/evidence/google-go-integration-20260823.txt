## Selected Android 10 payload

The local `vendor/partner_gms` tree contains:

* Google Services Framework, Google Play services and Play Store;
* Contacts and Calendar sync adapters;
* Google Go, Maps Go, Gallery Go base, Navigation Go and Gmail Go;
* two version-matched GmsCore language/density splits;
* seven app-private 32/64-bit JNI sidecars;
* the one Android Q activity-recognition split-permission mapping.

There are exactly 20 payload files totaling 232225898 bytes. The broad
ExtraFilesGo Pixel/VR/feature/permission payload is not installed.

Compatibility exclusions are deliberate:

* Assistant Go requires minSdk 31 and cannot be installed on SDK 29.
* Gallery Go's two supplied splits use versionCode 2761332 while the base uses
  12250740; Android Q rejects that cluster. The base is not split-required and
  is installed alone.

## Lineage/Q build integration

The product sets `WITH_GMS=true` and `WITH_GMS_GO=true` before inheriting
Lineage common configuration. Lineage's native
`vendor/partner_gms/products/gms_go.mk` entry point installs every component
under product, which resolves to `/system/product` inside this A-only
`system.img`.

All ten base APKs use Q's `LOCAL_REPLACE_PREBUILT_APK_INSTALLED` path and are
PRESIGNED. This copies the file without zipaligning, uncompressing dex/JNI or
re-signing. The two GmsCore splits are exact ETC prebuilts in the base APK
directory with globally unique output basenames and explicit PRESIGNED package
metadata. Dexpreopt is disabled for the first bring-up.

Q's `prebuilt_etc_xml` factory has a path bug and places product XML at the
partition root. The integration instead uses `prebuilt_etc` for the correct
`product/etc/{permissions,default-permissions,sysconfig}` paths and pairs each
with a non-installable `prebuilt_etc_xml` validation module.

## Permission and identity audit

The privileged allowlist is the exact intersection of each APK's requested
permissions with this Android Q framework's signature|privileged definitions:

    com.google.android.gsf                19 required / 19 allowed
    com.google.android.gms                56 required / 56 allowed
    com.android.vending                   29 required / 29 allowed
    com.google.android.apps.searchlite     1 required /  1 allowed

There are no missing or extra Q privileged grants. Runtime default permissions
are limited to five revocable (`fixed=false`) Contacts/Calendar synchronization
grants. Interactive Google applications receive no silent microphone, camera,
location, SMS or phone permission.

GSF and GmsCore both use shared UID `com.google.uid.shared` and the same
SDK-29 signer. Core GSF/GMS/Play certificate SHA-256 is:

    f0fd6c5b410f25cb25c3b53346c8972fae30f8ee7411df910480ad6b2d60db83

The full system trust given to GMS remains explicit: hidden-API, location,
Doze/data-saver and package-management privileges are inherent in full GMS,
not an accidental broad XML import.

## Offline build verification

Targeted module builds pass. All 19 APK/SO artifacts which existed before the
split-permission addition compare byte-for-byte between the imported source
and current product output; the twentieth XML is hash- and xmllint-verified.
All twelve APK/base/split files pass apksigner and 4 KiB zipalign checks. Every
base minSdk is at most 29, and no base has a required uses-library dependency.

The GmsCore base, config.en and config.xxhdpi files share package name
`com.google.android.gms`, versionCode `214218037`, and the same signer. The
generated apkcerts list contains all ten base APKs and both uniquely named
splits as PRESIGNED.

Tier 3 release signing now parses the actual installed APK set and compares
every PRESIGNED target-files entry before and after release signing. Any
single-byte mutation aborts publishing.

## Native reachability and residual tests

Six Phonesky JNI sidecars are ARM32 and Navigation Go's JNI sidecar is ARM64,
matching this device's dual-ABI userspace. All normal dependencies close.
`libphonesky_data_loader.so` alone names Android 11 `libdataloader` and
`libincfs`; its service is disabled by default and enabled only by the APK's
v30 resource, making it unreachable on SDK 29. Post-flash validation must keep
that component disabled and check for linker errors while installing/updating
an application from Play Store.

The payload is suitable only for the owner's private device. Publishing the
proprietary directory, system.img, target-files, OTA or full ROM would also
redistribute Google binaries and is outside this integration's release model.

Post-flash gates remain: PackageManager scan with no parse/shared-UID/privapp
errors; GSF/GMS/Play stable processes; account login; Play install/update;
Contacts/Calendar sync; GmsCore splitCodePaths; FCM/Doze behavior; and a new
SELinux capture.
