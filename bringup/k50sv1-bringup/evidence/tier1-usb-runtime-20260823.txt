## Host failure signature before intervention

Repeated kernel events for the handset's normal-system USB gadget:

    idVendor=18d1, idProduct=4ee7, bcdDevice=ff.ff
    no configurations
    can't read configurations, error -22
    unable to enumerate USB device

`adb devices -l` had no USB transport. This fails before ADB authorization or
host udev permissions can matter.

## Device state through direct root network ADB

    uid=0(root) ... context=u:r:su:s0
    getenforce=Permissive
    sys.boot_completed=1

    /sys/class/android_usb/android0/functions: empty
    /sys/class/android_usb/android0/f_ffs/aliases: empty

The generic AOSP fallback selected an ADB VID/PID but had no mounted FunctionFS
instance or alias from which the legacy android_usb driver could construct an
ADB configuration descriptor.

## Reversible runtime probe

The probe created and mounted `/dev/usb-ffs/adb`, disabled the gadget before
writing `f_ffs/aliases=adb`, selected the legacy adbd properties, and restarted
adbd. Result:

    functionfs mounted at /dev/usb-ffs/adb
    f_ffs/aliases=adb
    functions=ffs
    ep0, ep1 and ep2 present
    sys.usb.ffs.aio_compat=1
    persist.adb.nonblocking_ffs=0
    init.svc.adbd=running

This proves the missing normal-boot FunctionFS/legacy-I/O chain. The final host
enumeration check could not run because the device UDC then reported
`not attached` and the host observed no new physical USB insertion. No
partition was modified by this probe.
