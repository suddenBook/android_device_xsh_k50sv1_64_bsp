## Callback lifetime boundary

Pointer withdrawal is not a wait for active callbacks. This is a reachable k50sv1 boundary, not merely a generic API caveat. The build14 product config has CONFIG_MODULE_UNLOAD=y, CONFIG_MTK_COMBO_WIFI=y, CONFIG_THERMAL=y and CONFIG_MTK_CONNECTIVITY_SOURCE=m. Its System.map resolves mtk_wcn_cmb_stub_query_ctrl as a strong built-in symbol, and contains wmt_thz_get_temp and thermal_zone_device_check. Connectivity Makefile builds connadp into the kernel; the source common Makefile builds the stub and platform code into wmt_drv.

Actual chain: thermal sysfs temp_show (drivers/thermal/thermal_core.c:535-542), or policy-enabled thermal_zone_device_check (:514-519), -> thermal_zone_get_temp (:421-435) -> mtk_thermal_wrapper_get_temp (mtk_thermal_monitor.c:1791-1810) -> wmt_thz_get_temp (mtk_ts_wmt.c:586-597; ts_get_temp_wrap[0] at :86-87) -> built-in mtk_wcn_cmb_stub_query_ctrl (wmt_build_in_adapter.c:89-96) -> module _mtk_wcn_cmb_stub_query_ctrl (mtk_wcn_stub_alps.c:286-295) -> wmt_plat_thermal_ctrl (wmt_plat_alps.c:258-264) -> wmt_dev_tm_temp_query (wmt_dev.c:853-999), which can execute blocking therm-control commands (:939-941). Default thermal polling is zero (:1757); policy may enable it, and sysfs reads remain an explicit entry. This review did not assert that polling was currently enabled on the handset.

Normal module exit is wmt_detect_driver_exit (:368-372) -> WMT_exit (:1976), which clears the thermal callback at :1999 and later runs wmt_lib_deinit -> wmt_plat_deinit -> stub unregister. These are raw pointer writes. Neither bridge registration/dispatch nor unregistration obtains a module reference or waits for callbacks; WMT exit does not unregister the built-in thermal zone or acquire its mutex. Other dependent modules/open WMT file handles may prevent unload while their references exist, but the thermal bridge invocation itself does not acquire such a reference. Once ordinary users release those references, a thermal invocation can still overlap teardown. An op-pool borrow only covers the individual WMT operation, not the complete outer thermal callback and its module return address.

The scoped platform candidate improves ordering and does not claim complete quiescence. Its sequential fixture does not test an already-entered callback or the real thermal payload. The separate callback-lifetime task will address the missing admission/drain barrier. No hardware overlap or module-unload experiment was performed during this read-only review.
