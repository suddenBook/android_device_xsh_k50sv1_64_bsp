# Proprietary files for k50sv1_64_bsp
#
# Source: immutable factory_image_unpacked filesystem, never the rooted live
# device. Entries are grouped by runtime subsystem and reviewed before use.
#
# Each section header ends in "-- section: <tag>", and extract-files.sh -s <tag>
# resolves against those tags. Do not pass a bare subsystem word: extract_utils
# turns --section into a sed range that starts at every comment containing the
# string and ends at the next blank line, and because sed restarts a range as
# soon as it closes, a word appearing in more than one comment silently selects
# the UNION of several sections. "-s ims" used to extract Radio and IMS
# together (90 entries instead of 27) and "-s media" the whole Audio tail plus
# Media OMX (153 instead of 25). extract-files.sh now rejects any name that does
# not resolve to exactly one section and prints the valid tags.
#
# Deliberate exclusions:
# - fingerprint feature/HAL/service/app/policy
# - SecPenNote and Stock S Pen popup/sound UI
# - ADUPS FOTA, Facebook, fake Samsung/UMIDIGI identity and product overlays
# - EngineerMode/ATCI/factory test/logging packages unless a measured runtime
#   dependency proves they are required
# - Stock fstab, assembled VINTF, generated/precompiled SELinux policy
# - libmtk-rilop.so and vendor.mediatek.hardware.radio_op@2.0.so. Working
#   open-market stock loads them and publishes four IRadioOp instances, so they
#   are a real call/IMS parity risk, not an inapplicable carrier add-on. They do
#   not participate in PLMN attach and are deferred until after the clean slot-0
#   registration control; restoration must include both blobs, VINTF and policy
#   as one measured change.
#
# A leading '-' packages a Stock library as a preferred prebuilt module. For
# modules that also exist in AOSP, keep every real Stock 32/64 variant, without
# exception. Soong resolves a `prefer: true` prebuilt against the source module
# by variation, so a prebuilt that omits one architecture cannot satisfy a
# source module that builds both, and the build dies at bootstrap:
#
#   error: hardware/interfaces/graphics/composer/2.1/default/Android.bp:1:1:
#   failed to find variation "android_arm_armv8-a_cortex-a53" for module
#   "prebuilt_android.hardware.graphics.composer@2.1-impl" needed by
#   "android.hardware.graphics.composer@2.1-impl"
#
# "the second variant has no loader on this device" is a true statement about
# the hardware and an invalid reason to drop it. Blobs with no AOSP counterpart
# have no such constraint and may ship whichever architectures are real.

# libeffects (the audio effect factory) and libeffectproxy are built from AOSP
# source; they are deliberately NOT shipped as prebuilts. Both are in
# PRODUCT_PACKAGES unconditionally via build/make/target/product/base_vendor.mk
# (libeffects, libeffectproxy), so something must provide them -- AOSP does,
# correctly.
#
# An earlier revision shipped both as prebuilts because dropping libeffectproxy
# on its own made the build fail with
#   frameworks/av/media/libeffects/proxy/EffectProxy.cpp:30:10: fatal error:
#   'media/EffectsFactoryApi.h' file not found
# and that was misread as a defect in AOSP Q. It is not. libeffectproxy reaches
# that header through libeffects, which re-exports libeffects_headers'
# export_include_dirs (frameworks/av/media/libeffects/factory/Android.bp). But
# extract_utils emits cc_prebuilt_library_shared with no export_include_dirs,
# and `prefer: true` substitutes the prebuilt for the source module throughout
# the dependency graph -- so the libeffects *prebuilt* was itself what deleted
# the include path from its consumers. Remove the two together and the source
# builds. Neither blob was reachable at runtime anyway: libeffectproxy is not
# named in the active <libraries> block of vendor/etc/audio_effects.xml.
#
# General rule, and the reason this is spelled out: a `prefer: true` prebuilt of
# a library whose AOSP source exports headers will silently break that
# library's source consumers. Ship one only when the library is genuinely
# SoC-modified.

# ePDG / VoWiFi data plane  -- section: vowifi
# The IMS section above is voice-over-LTE only. This one is the userspace ePDG
# tunnel, which MediaTek runs in Android rather than in the modem:
#
#   epdg_wod  resolves epdg.epc.mnc<MNC>.mcc<MCC>.pub.3gppnetwork.org (or the
#             operator FQDN from wod_optr.conf), writes one strongSwan conn
#             fragment per PDN into /data/vendor/ipsec/wo/, forks
#             `starter --daemon charon`, drives tunnels with `stroke`, and
#             installs the two oem_epdg_* iptables chains through
#             /system/bin/iptables-wrapper-1.0.
#   wfca      carries IMS media between /dev/ccci_imsa and marked sockets on
#             wlan0 while a WFC call is up.
#   libmal_epdga.so   MAL's ePDG entity, loaded in-process by mtkmal, which is
#             ELF32 -- so the 32-bit libwo.so has to ship beside it.
#
# The DT_NEEDED closure over all of these terminates in bionic, libcutils,
# liblog and libz with zero unresolved sonames. The kernel needs nothing: XFRM,
# XFRM_USER, NET_KEY, INET{,6}_ESP, INET_XFRM_MODE_TUNNEL, TUN,
# NETFILTER_XT_MATCH_POLICY, NETFILTER_XT_TARGET_TCPMSS, NF_NAT and the whole
# AES/SHA/HMAC/CBC/CTR/GCM/XCBC set are =y on this handset (/proc/config.gz).
# Only CRYPTO_CCM is absent, and no profile in wod_optr.conf proposes AES-CCM.
#
# The init rc files are NOT extracted. rootdir/etc/init/init.wfca.rc and
# init.epdg_wod.rc own them so the two deliberate departures from Stock stay
# reviewable as a diff -- see the headers of those files.
#
# DELIBERATELY EXCLUDED, each for a measured reason:
#
#   vendor/bin/ipsec_mon, vendor/etc/init/ipsec_mon.rc
#       Not part of the ePDG tunnel. It watches XFRM netlink for the SIP-IPsec
#       SAs that libipsec_ims_shr.so installs inside volte_stack and publishes

#       registers on this image today without it. Its own stage, not this one.

# DRM / Widevine (Level 3, legacy drm@1.0 plugin path)  -- section: drm
# The port serves DRM with AOSP's android.hardware.drm@1.0-impl/-service, which
# dlopens plugins from getDrmPluginPath() -- /vendor/lib/mediadrm for a 32-bit
# service, /vendor/lib64/mediadrm for a 64-bit one
# (hardware/interfaces/drm/1.0/default/LegacyPluginPath.cpp). AOSP forces that
# service to 32-bit unless TARGET_ENABLE_MEDIADRM_64 is set
# (drm/1.0/default/common_default_service.mk), so today only the 32-bit copy is
# ever loaded; the 64-bit copy is kept so flipping that board flag stays a
# one-line change instead of a silent loss of DRM.
#
# The Stock blob exports the legacy createDrmFactory/createCryptoFactory ABI in
# both architectures, which is exactly what @1.0-impl's PluginLoader looks for,
# and its DT_NEEDED closure is entirely VNDK/LLNDK (libbase, liblog,
# libprotobuf-cpp-lite, libstagefright_foundation, libutils) -- nothing
# MediaTek-specific, so it needs no other blob.
#
# Stock instead runs its own android.hardware.drm@1.2-service.widevine backed
# by libwvhidl.so under the "widevine" instance name. That path is NOT ported:
# it would need the service, libwvhidl, three more manifest <fqname> entries and
# its own SELinux domain, for a newer HIDL minor version this device gains
# nothing from. The @1.0 instance is already declared in manifest.xml.
#
# Level 1 needs an OEMCrypto root of trust in the TEE that this clone does not
# provision -- the blob itself logs "Bad Level 1 Root of Trust. Falling Back to
# L3." -- so this is Widevine L3: SD streaming and DRM audio, not HD.
# /data/vendor/mediadrm is created by rootdir/etc/init/init.mediadrm.rc and
# labelled by sepolicy/drm.
